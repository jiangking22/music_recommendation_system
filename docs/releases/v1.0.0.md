# Sonora v1.0.0 — Explainable Music Recommendation / 可解释音乐推荐

Sonora combines a deterministic multi-source music recommender with a bounded assistant.
This first planned repository release brings together the engineering phases already merged
into main. It is a runnable engineering demonstration with explicit limits on data and model quality.

Sonora 将确定性多源推荐与受控音乐助手结合。本次拟发布汇总已合并的工程成果；推荐器负责评分与顺序，
Agent 调用工具并解释结果。小曲库与离线评估用于展示和回归验证，不代表真实用户效果。

## Highlights / 主要内容

- **Engineering foundation:** Next.js/TypeScript, FastAPI typed `/v1` APIs, PostgreSQL/pgvector,
  Redis readiness, five Alembic migrations and a local Docker Compose setup.
- **Providers:** canonical music models, iTunes and best-effort NetEase defaults, optional QQ,
  bounded calls and partial-source errors. Local catalog fallback keeps recommendation available.
- **Recommendation/personalization:** deterministic recall/deduplication/scoring/diversity,
  factor explanations, durable like/dislike feedback and anonymous preference snapshots.
- **Product client:** responsive recommendation cards, provenance, explanations, feedback and
  preference views, plus clear loading/empty/error states.
- **Agent/RAG/MCP:** one allowlisted Agent, local router or optional OpenAI-compatible adapter,
  six-turn memory, four-document RAG, JSON/SSE chat and two read-only standard MCP stdio tools.
- **Observability/CI:** correlated JSON events, safe errors, bounded request bodies,
  API/web tests and a real offline Compose clean-start gate.

## Run locally / 本地运行

Requirements: Docker Compose v2 for the complete stack. Manual development uses Python 3.12,
Node.js 24/npm 11, PostgreSQL 16 with pgvector, and Redis 7.

```bash
git clone https://github.com/jiangking22/music_recommendation_system.git
cd music_recommendation_system
cp .env.example .env
# PowerShell: Copy-Item .env.example .env
# Set POSTGRES_PASSWORD and the matching, URL-encoded password in DATABASE_URL.
# For the reproducible demo: ENABLE_MUSIC_PROVIDERS=false, LLM_PROVIDER=local, LLM_API_KEY empty.
docker compose config --quiet
docker compose up --build --wait --wait-timeout 180
```

The clone command follows the current default branch; this draft does not reference a nonexistent tag.
Open [recommendations](http://localhost:3000), [assistant](http://localhost:3000/agent) and
[API docs](http://localhost:8000/docs). Startup applies migrations. No music-provider or LLM
credentials are needed in the offline demo; first-build package/image downloads still need network.

完整步骤、环境变量和回退说明见 [Deployment](https://github.com/jiangking22/music_recommendation_system/blob/main/docs/DEPLOYMENT.md)；
五分钟流程见 [Demo](https://github.com/jiangking22/music_recommendation_system/blob/main/docs/DEMO.md)。
旧版入口仍可用：在仓库根目录执行 `python server.py`，按终端打印的地址打开。

## Known limits and release status / 限制与发布状态

- No repository LICENSE is present and no license has been chosen during preparation.
- API/web package metadata and OpenAPI currently say `0.1.0`; the relationship to the planned
  repository `v1.0.0` must be resolved before publishing this draft.
- Anonymous IDs provide preference linkage, not authentication. No account recovery,
  cross-device sync, chat-history/deletion UI, automatic retention sweep or distributed rate limiter.
- NetEase/QQ endpoints are undocumented; real-model compatibility and quality remain unverified.
  Local routing is rule based. No licensed playback/full streaming is provided.
- RAG/catalog fixtures are small; 16D hashes have collisions. MCP supports local stdio;
  retained `/v1/mcp` HTTP routes are a façade, not standard remote MCP HTTP/OAuth.
- Redis caching is unimplemented. JSON telemetry has no hosted collector or alert service.
  Transitive Python dependencies and container images are not hash/digest locked.
